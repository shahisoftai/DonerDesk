# Understanding Evidence Verification

Evidence verification is the process of confirming that uploaded evidence is genuine, relevant, and accurate.

## Why Verification Matters

Donors require evidence that is:
- **Genuine** — The file is real and unaltered
- **Relevant** — It proves the claimed activity or result
- **Accurate** — The content matches what it claims

Without verification, any file could be submitted as evidence.

## Evidence Verification Statuses

| Status | Meaning |
|--------|---------|
| **Uploaded** | Just uploaded, not yet reviewed |
| **AI Tagged** | AI has suggested tags for classification |
| **Pending Review** | Awaiting human review |
| **Verified** | Reviewed and confirmed as valid |
| **Needs Correction** | Has an issue that needs to be fixed |
| **Rejected** | Cannot be used as evidence |
| **Archived** | Old or superseded evidence |

## The Verification Process

### Step 1: Upload

Anyone on the project team uploads evidence. It starts with status "Uploaded".

### Step 2: AI Tagging

Within moments, AI analyses the document and:
- Suggests tags (evidence type, sector, etc.)
- Extracts text for search
- Flags potential sensitivity issues

Status changes to "AI Tagged".

### Step 3: Human Review

A designated reviewer (M&E Officer, Compliance Officer) checks:

1. **File authenticity** — Is this a real document?
2. **Relevance** — Does it prove what it claims to prove?
3. **Metadata accuracy** — Is the date, location, title correct?
4. **Linked correctly** — Is it connected to the right activity?
5. **Quality** — Is the document clear and readable?

### Step 4: Verify or Request Correction

**If everything looks good:**
- Click **Verify**
- Status changes to "Verified"

**If there is an issue:**
- Click **Needs Correction**
- Add a note explaining what needs to be fixed
- The uploader is notified

### Step 5: Resolution

The uploader:
- Makes the requested changes
- Re-uploads or updates the evidence
- Status returns to "Pending Review"

## What Reviewers Check

### For Attendance Sheets

- Date matches the claimed activity date
- Location is correct
- Number of participants matches the activity log
- Signatures or names present
-organisation seal if required

### For Photos

- Date and location identifiable
- Activity clearly depicted
- No inappropriate content
- Appropriate consent for identifiable people

### For Reports

- Authorised signatory present
- Official seal/stamp if required
- Date matches the activity period
- Content matches the claimed activity

### For Financial Documents

- Authorised signatures present
- Amounts match budget/procurement records
- Official receipts/invoices provided
- No calculation errors

## Verification Tips

### For Uploaders

1. **Check before uploading** — Verify the file is complete and readable
2. **Fill in metadata correctly** — Date, location, activity links
3. **Respond to correction requests** — Fix issues quickly
4. **Keep originals** — Keep source documents in case of queries

### For Reviewers

1. **Check systematically** — Use a checklist
2. **Verify links** — Make sure evidence connects to activities
3. **Be timely** — Backlogs delay reporting
4. **Document decisions** — Add notes when accepting borderline evidence

## Verification and Compliance

The compliance checklist considers evidence verification:
- Unverified evidence may not count as resolved
- Verified evidence is required for compliance
- High-severity compliance items require verified evidence

## Rejecting Evidence

Evidence should be rejected if:
- It is fraudulent or altered
- It does not relate to the claimed activity
- It is a duplicate of existing evidence
- It contains inappropriate content

When rejecting:
1. Click **Reject**
2. Add a clear explanation
3. Suggest what new evidence would satisfy the requirement
