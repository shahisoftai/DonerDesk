# How to Run a Reporting Month, Step by Step

This is the whole routine in one page. Do it once a month (or once per reporting period) and your report is nearly written before you start. Each step links to a short guide.

**One-time first:** the project must be **Ready** (donor template approved, logframe and indicators in place). If not, see [Getting started](/support/getting-started/getting-started).

## Before the month starts

1. **Create the periods.** On **Reporting**, use **Create all periods** to set up the whole calendar in one click. See [How to create a reporting period](/support/how-to/create-a-reporting-period).
2. **Check the template.** Each report type uses its approved donor template automatically. To use another one, see [How to change a report's template](/support/how-to/change-a-reports-template).

## During the month (the field team)

3. **Log each activity as it happens.** One form: what happened, when, where, who came, and the proof files. Drop the files on the form; they join the activity and the right period by themselves. See [How to log activities](/support/how-to/log-activities).
4. **Add evidence later if you must.** Open the activity and click **Add evidence**. See [How to upload evidence](/support/how-to/upload-evidence).

## End of the month (the M&E and project team)

5. **Review activities.** Accept them all at once, ask for a fix, or withdraw a duplicate. See [How to review and accept activities](/support/how-to/review-and-accept-activities).
6. **Enter indicator values** for the period and use **Verify all**. See [How to update indicator values](/support/how-to/update-indicator-values).
7. **Verify evidence.** See [Evidence verification](/support/getting-started/evidence-verification).
8. **Tell the story** (five short questions). See [How to tell the story](/support/how-to/tell-the-story-and-add-inputs).

## Write and approve

9. **Generate the draft.** See [How to generate an AI report draft](/support/how-to/generate-ai-report-draft).
10. **Review in the editor.** Follow the one big button at the top right. Fix or decide on flagged statements, read each section, approve. An approved section can still be edited: click **Edit (reopens section)**. See [How to use the report editor](/support/how-to/use-the-report-editor).
11. **Clear the checks.** Items that depend on your data close when you run **⋯ → Scan for missing items**; the rest need a person. See [How to use the compliance checklist](/support/how-to/use-compliance-checklist).
12. **Submit, approve and export.** See [How to review and approve reports](/support/how-to/review-and-approve-reports) and [How to export reports](/support/how-to/export-reports).

## At the end of the project

13. **Create the closing report** from its guided page. It covers the whole life of the project. See [How to create the closing report](/support/how-to/create-the-closing-report).

## A good rhythm

| When | Who | What |
|---|---|---|
| As it happens | Field officers | Log activities with proof |
| Weekly | M&E officer | Accept activities, verify evidence |
| Month end | M&E officer | Indicator values, Verify all |
| Month end | Project manager | Story, draft, review, approve |

## If something looks wrong

Most problems have a simple fix: a wrong parent on an indicator ([fix it](/support/how-to/fix-or-remove-an-indicator)), a duplicate activity ([withdraw it](/support/how-to/review-and-accept-activities)), or the wrong template ([change it](/support/how-to/change-a-reports-template)). Nothing needs rebuilding.
