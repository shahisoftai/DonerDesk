# Imported vs. Linked Data

DonorDesk works with your data in two ways.

## Linked (stays where it is)

- **Evidence in Google Drive:** DonorDesk stores a reference to the file. The file stays in your Drive under your control and does not use your DonorDesk quota.
- If a verified file changes after verification, DonorDesk flags it (stale verification / evidence hash mismatch) and asks you to re-verify.
- If you lose access to the file in Drive, it cannot be read by DonorDesk.

## Imported (copied into DonorDesk)

- **Excel/CSV imports** of logframe, indicators, activities and evidence records create DonorDesk records. Later edits to your spreadsheet do not change them.
- **Google Sheets import** of indicator values copies the values into the grid when you import and save. It is not a live sync.
- **DonorDesk-managed uploads** are stored by DonorDesk and count toward your storage.

## Which to use

| Situation | Choose |
|---|---|
| Files your organisation already keeps in Drive | Link |
| Records you want DonorDesk to own and report on | Import |
| No Google account | DonorDesk storage |

Text from documents is read so AI drafts can cite it, whichever way the file is held.

See [Storage and file management](/support/getting-started/storage-file-management).
