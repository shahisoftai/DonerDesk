# Understanding Indicators and Targets

An **indicator** is how you measure a result. A **target** is the value you plan to reach.

## Fields

| Field | Notes |
|---|---|
| Name and code | Short, stable codes (OUT-1) are used for imports. |
| Type | Number, Percentage, Yes/No, Text, Ratio, Currency or Custom. |
| Logframe item | The goal, outcome, output or activity it measures. |
| **Baseline** | The starting value. |
| **Target** | The value to reach by the end. |
| Unit | For example people, %, USD. |
| Frequency | How often it is measured. |
| Data source / Means of verification | Optional; where the figure comes from and how it is proven. |
| Record a breakdown | Optional. Enter results split by sex, age group and disability. On by default for indicators that count people. |

Baseline, target, unit and frequency are required for quantitative indicators before a project is reporting-ready.

## Changing an indicator later

An indicator can be edited, moved to another logframe item or removed at any time (see [How to fix, move or remove an indicator](/support/how-to/fix-or-remove-an-indicator)). Its type is locked once a value is recorded. An indicator with recorded values is **archived**, not erased, so earlier reports keep their history; one used in an approved report cannot be removed or moved until the report is sent back for changes.

Several indicators can measure the same logframe item.

## Period values

For each reporting period you enter the **period achievement** in the indicator grid. See [How to update indicator values](/support/how-to/update-indicator-values).

## How values are combined

Set the indicator's **reporting basis**: latest value, sum of period values, average, highest, lowest or cumulative to date. Percentages and ratios use a **numerator ÷ denominator** calculation from two other indicators. Set **direction of progress** (higher is better, lower is better, neutral).

### Confirming the calculation

Every indicator shows how reports will use it, in plain words: for example **Counts: summed across periods. Not evaluated against the target. Needs review.** or **Rate: latest reported value.** A badge on the logframe page says **Calculation needs review** or **Calculation confirmed**.

DonorDesk suggests a calculation from the indicator's type, unit and name, but a suggestion is not a decision. Until you confirm it, the report only *describes* the indicator and does not say whether it is on track. To confirm:

- click **Confirm calculation** on the indicator (or **Confirm all** on the logframe page) to accept the suggestion in one click, or
- open the indicator and choose another calculation, direction and basis.

A percentage that your team reports directly (for example an attendance rate from registers) is confirmed as **latest reported value**; no numerator or denominator is needed. A rate calculated from two other indicators needs both chosen. Confirming never picks a direction for you: unless you choose "higher is better" or "lower is better" the indicator stays neutral.

Indicators that still need confirming appear as a warning on the project's Setup page and as checklist items that close themselves once you confirm.

## Progress

The indicator page shows **progress toward target** (share of the distance from baseline to target), the latest period breakdown and the update history.

## Verification

Each update is Draft → Submitted → **Verified** (or Needs correction / Rejected). Reports use verified values and mark unverified ones.

## Good practice

- Set baselines and targets from the donor's agreement.
- Enter values every period and link evidence.
- Keep indicator names identical to the donor's wording.
